## Автоматизированный сценарий для среды с рабочей авторизацией

Требуются Node.js 22, Git, официальные GitHub CLI (`gh`) и Vercel CLI (`vercel`), а также доступ к указанным аккаунту и проекту. Вход выполняется через официальные процедуры CLI/браузера. Пароли и токены не нужно записывать в сайт или отправлять в чат.

```sh
# Только локальные проверки — ничего не публикует.
bash DEPLOY.sh --check

# Выгрузка в отдельный приватный GitHub-репозиторий,
# подключение Git к точно указанному существующему Vercel-проекту,
# затем preview-деплой.
bash DEPLOY.sh --preview

# Публикация в Production; команда изменит работающую версию указанного проекта.
bash DEPLOY.sh --production
```

**Сценарий подготовлен; его удалённые операции в этой среде не выполнялись.** Проверены синтаксис Bash и режим `--check`. Реальное создание репозитория, связывание Git и деплой требуют работающей авторизации и подтверждения результатов CLI.

При несовпадении GitHub-аккаунта, Vercel Project ID, Git remote или истории репозитория сценарий останавливается. Перезаписи чужой истории и force-push нет. При частичном сбое GitHub-репозиторий может уже быть создан, но Vercel ещё не опубликован; это различается по выводу CLI.

## Через интерфейсы GitHub и Vercel

Создать отдельный приватный репозиторий `treolympus` в аккаунте `sekl28` либо использовать уже созданный пустой репозиторий. Загрузить содержимое папки проекта, включая скрытую папку `.github`. Не загружать ZIP как единственный файл: хостингу нужны распакованные исходники.

В существующем Vercel-проекте `treolympus` открыть Settings → Git и подключить этот репозиторий. Корень проекта — `./`. В `vercel.json` уже заданы Other, `npm run build`, `dist`. Для Production выбрать `main` и выполнить деплой.

После статуса Ready отдельно проверить страницу на production-домене, мобильное меню, EN/FR, переход по кнопке и отсутствие доступа к служебным файлам. Успешная локальная сборка не подтверждает HTTPS, DNS, наличие Production deployment или учёт переходов партнёрским кабинетом.
